8개의 기록
2026.01.10 기획

아이디어를 프로젝트로 구체화하기

떠오른 아이디어를 실제로 만들 수 있는 프로젝트로 발전시키기 위해 목표와 필요한 기능을 정리하는 단계.

이 단계에서는 어떤 문제를 해결할지, 누가 사용할지, 핵심 기능은 무엇인지 구분해.

  • 프로젝트의 목적 정의
  • 필수 기능과 선택 기능 구분
  • 실현 가능성과 필요한 도구 검토
2026.02.05 개발

웹 기술로 첫 화면 만들기

HTML로 구조를 만들고 CSS로 디자인을 적용한 뒤, JavaScript로 사용자 상호작용을 구현하는 과정.

화면을 구성하는 것과 기능을 구현하는 것을 분리하면 수정과 확장이 쉬워져.

  • HTML 문서 구조 작성
  • CSS 반응형 레이아웃 적용
  • JavaScript 이벤트 처리
2026.03.01 디자인

브랜드의 시각적 방향 설정

보라색과 하늘색을 중심으로 기술적인 느낌과 깔끔한 사용자 경험을 결합하는 디자인 방향을 탐구해.

디자인은 장식뿐 아니라 정보의 우선순위와 사용자가 기능을 이해하는 방식에도 영향을 줘.

  • 색상과 글꼴 체계 정리
  • 버튼과 카드의 공통 스타일 설계
  • 모바일 화면에서의 사용성 검토
2026.04.12 개발

프런트엔드와 백엔드 연결 이해하기

화면에서 입력한 데이터를 서버에 전달하고, 서버의 응답을 화면에 표시하는 구조를 살펴봐.

브라우저와 서버의 역할을 나누면 API와 인증, 데이터 저장 같은 기능을 더 체계적으로 설계할 수 있어.

  • HTTP 요청과 응답 이해
  • API 경로와 데이터 형식 설계
  • 오류 응답과 연결 실패 처리
2026.05.20 인공지능

인공지능 실험 영역 확장

데이터를 활용하는 모델과 규칙 기반 프로그램의 차이를 이해하고, 실제 결과를 비교하는 방향을 탐구해.

모델이 그럴듯한 결과를 출력하는 것만으로는 충분하지 않아. 학습 데이터, 검증 데이터, 평가 방법을 함께 살펴봐야 해.

  • 데이터 수집과 정리
  • 학습과 검증의 차이 이해
  • 기준 모델과 결과 비교
2026.06.15 보안

안전한 서비스 구조 고민하기

공개된 웹페이지에 비밀 키를 넣지 않고, 서버에서 중요한 작업을 처리하는 구조를 살펴봐.

프런트엔드 코드는 사용자에게 전달되므로 비밀 정보를 숨기는 장소로 사용할 수 없어.

  • 서버 환경변수로 비밀 키 관리
  • 인증과 권한 확인
  • 입력값 검증과 오류 처리
2026.08.02 기획

여러 프로젝트가 공유할 구조 구상

공통 기능을 모듈로 분리하고, 프로젝트 사이에서 재사용할 수 있는 구조를 생각해.

공통 코드를 분리하면 같은 기능을 여러 번 구현할 필요가 줄어. 대신 모듈 사이의 의존성과 버전 관리도 고려해야 해.

  • 공통 기능과 개별 기능 분리
  • 명확한 입력과 출력 정의
  • 호환성과 테스트 기준 설정
2026.10.12 개발

  • 공통 CSS와 JavaScript 구성
  • 다섯 개 페이지의 연결
  • 모바일 반응형과 접근성 점검
